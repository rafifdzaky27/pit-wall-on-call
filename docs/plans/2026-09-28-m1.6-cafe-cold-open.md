# M1.6: Café Cold Open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every shift opens in a café in the incident's city. The player can:
- look around the café, and find clues at the next table and on the wall
- zoom into the laptop (which is the live PitOS desktop) and back out
- feel the phone buzz on the table when the page fires

After the fix holds for a visible 10-second countdown, the camera pulls back to the café for a cold close. The café has recorded ambience and a lo-fi radio generated in the browser. The three bugs found after #19 and every deferred minor are fixed.

**Architecture:**
- **Stage:** a `Stage` component in the main chunk wraps the Desktop and owns the camera (`desktop` or `cafe`).
  - In the café, the whole live Desktop is scaled into the laptop's screen rectangle with one CSS transform, and made `inert`.
  - Zooming is a single transform animation on a wrapper around both layers.
- **Café scene:** an SVG renderer in a lazy chunk, driven by a pure, seeded `resolveScene()` in `packages/world`.
- **Audio:** `os/sound.ts` becomes `os/audio/`, an `AudioEngine` with four buses and a café low-pass filter, plus a generative `LofiRadio` and an ambience loader with a silent fallback.
- **Engine:** gains one read-only snapshot field, `stableSinceTick`, for the fix-hold countdown. Scoring does not change.

**Tech Stack:** TypeScript ~6.0, pnpm 10.12.2, React 19, Vite 8, Vitest 5, Testing Library (jsdom), @playwright/test, Web Audio, Web Animations.

**Spec:** `docs/specs/2026-09-28-cold-open-design.md` (M1.6 refresh, C1–C11, §6–§13), plus `docs/specs/2026-09-28-pitos-polish-design.md` and `docs/DESIGN.md`.

## Global Constraints

- **Copy:** English and sentence case in PitOS and café controls. In-world text (café signs and menus, the store, chat) uses the city's language.
- **No emoji and no decorative icons** in PitOS or café controls. Café controls are text buttons.
- **No dead controls:** a control that cannot work is not rendered.
- **Tokens:**
  - Colours, sizes, durations and layers come from `apps/web/src/styles/tokens.css`.
  - The exceptions are art and in-world pages. The café palettes live in `packages/world/src/scene.ts`.
- **Motion:** only `transform` and `opacity` are animated. Everything is instant under Settings → Reduce motion or `prefers-reduced-motion`. Camera moves become cuts. Parallax and particles stop.
- **Status:** always shown as a word or number, never colour alone.
- **Audio:**
  - No audio-only information.
  - Recordings are CC0 or public domain only, MP3 mono at 64 kbps, 1.5 MB or less in total, and lazy-loaded after Start shift.
  - All audio stops while paused, locked, or while the tab is hidden.
- **Shortcuts:** single-key shortcuts stay ignored in text fields and with a modifier held, and can be switched off.
- **Storage:** `localStorage` is always wrapped in try/catch.
- **Dependencies:** no new runtime dependencies.
- **Scores:** unchanged. `pnpm --filter @pitwall/scenarios test` (golden players) stays green, par stays 450, and `ENGINE_VERSION` stays `1.0.0`.
- **Budgets:**
  - The main JS chunk grows by no more than 3 KB gzip. It is 83,279 B today.
  - The café chunk is under 150 KB gzip.
  - Particles are capped at 300.
  - Store photos loaded per shift: 300 kB or less.
- **Commits:** conventional messages with **no AI attribution trailers**.

## Decisions made in this plan

| # | Topic | Decision | Why |
|---|---|---|---|
| R1 | Recordings | Two recordings from Wikimedia Commons: `Cafe ambiance.ogg` (CC0, by Marble Toast) and `Rain against the window.ogg` (public domain, by cori). The phone vibration is synthesized. | No CC0 or public-domain recording of a phone vibrating exists on Commons or OpenGameArt. A synthesized buzz through a low-pass filter sounds right. |
| R2 | "Fix did not hold" | Shown in the Monitoring hold indicator, not as an engine log line | An engine log line would change the log sequence. The engine gains only the read-only `stableSinceTick`. |
| R3 | Store categories | Each product gets a `category`. The bar shows "All" plus only the categories that have products, and the unused categories are removed from the data. | Three products per store. An empty category page never happens on a real marketplace. |
| R4 | Where the camera lives | `apps/web/src/cafe/Stage.tsx` in the main chunk; `CafeScene` is lazy | The Stage must exist before the café loads, so that it can show the fallback. |
| R5 | Paused overlay | Moves from `Desktop` to `Stage`, so it covers the whole screen in both camera states | Inside the scaled Desktop, it would be laptop-sized in the café. |
| R6 | Desktop shortcuts in the café | Only **A** (ack) and **P** (pause) act in the café. **L** is handled by the Stage. | O, M, X, [ and ] would change windows the player cannot see. |
| R7 | Music and the café filter | The music bus goes through the same low-pass filter as the ambience | The radio is on the café counter. On the laptop you hear it through the room. |
| R8 | Hint chime | Not added | The console has no hint system. |
| R9 | Seamless loops | Loops crossfade in the player (1.5 s overlap), not in the file | This avoids a fragile ffmpeg crossfade filter. |
| R10 | Choosing the recording segment | The script picks the 45 s (murmur) or 30 s (rain) window with the steadiest loudness | Claude cannot listen. Rafif checks the result by ear at the end. |
| R11 | e2e for a whole run | Uses Playwright's `page.clock` to fast-forward the run loop | A real run takes more than a minute. |
| R12 | Camera duration | `DUR.camera = 700` ms (ease-in-out) | Zooming across the café needs more than `--motion-slow` (240 ms). The spec allows "or longer". |

## Review Focus

1. **Camera input mid-zoom:** pressing L repeatedly, or acking during a zoom, must end in the camera state of the last input, with no stuck transform. Tested in Task 11.
2. **Viewport resize in the café:** the desktop stays inside the laptop screen after a resize. Tested in Task 11.
3. **Pause, lock or a hidden tab in the café:** all audio is suspended, café animations freeze, and both resume. Tested in Tasks 8 and 12.
4. **Keyboard-only players:** in the café, Tab reaches only café controls. After zooming in, focus lands in PitOS; after looking up, focus lands on the laptop hotspot. Tested in Task 13.
5. **Assets failing mid-shift:** a failed café chunk or ambience file leaves the game playable (fallback backdrop, no sound). Tested in Tasks 10 and 15.

```tsx
import { STABLE_TICKS_TO_RESOLVE, TICKS_PER_SECOND, type Snapshot } from "@pitwall/engine";
import { useEffect, useRef, useState } from "react";

export const BROKEN_MS = 5000;

export function HoldIndicator({ snapshot }: { snapshot: Snapshot }) {
  const since = snapshot.outcome === "running" ? snapshot.stableSinceTick : null;
  const before = useRef(since);
  const [broken, setBroken] = useState(false);
  useEffect(() => {
    const was = before.current;
    before.current = since;
    if (was !== null && since === null && snapshot.outcome === "running") {
      setBroken(true);
      const id = window.setTimeout(() => setBroken(false), BROKEN_MS);
      return () => window.clearTimeout(id);
    }
    if (since !== null) setBroken(false);
  }, [since, snapshot.outcome]);
  if (since !== null) {
    const held = snapshot.tick - since;
    const left = Math.max(0, Math.ceil((STABLE_TICKS_TO_RESOLVE - held) / TICKS_PER_SECOND));
    const secs = Math.min(10, Math.floor(held / TICKS_PER_SECOND));
    return (
      <span className="hold" role="status">
        Fix holding · {left} s
        <span className="hold-bar" role="progressbar" aria-label="Fix holding" aria-valuemin={0} aria-valuemax={10} aria-valuenow={secs}>
          <i style={{ transform: `scaleX(${secs / 10})` }} />
        </span>
      </span>
    );
  }
  return broken ? <span className="hold broken" role="status">Fix did not hold</span> : null;
}
```
