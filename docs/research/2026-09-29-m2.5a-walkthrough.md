# M2.5 PR A persona walkthrough: flow and clarity

- **Date:** 2026-09-29
- **Build:** branch `feat/m2.5a-flow`, production web build with the e2e API (Postgres in Docker).
- **Method:** Claude ran a scripted Playwright walkthrough (not a usability test with people). Every persona plays to the end, through the report. The incident clock is fast-forwarded with Playwright's clock. There is a screenshot per step, and console errors are logged.

## Findings

| # | Grade | What happened | Fix |

| W1 | Minor | The Monitoring header's "Mitigated · cause still active" tag was cut to "MITIGATE…" at 1440 px, next to the title. | The tag says "Cause still active". The top bar's status chip keeps the full phrase. A unit test covers it. |

## What worked

- **No console errors** on any path.
- **Rafif's case (finding F1) is answered.** Within a second of the failover completing, the top bar chip read "Mitigated · cause still active" and a notice said the incident was still open. 20 s later the secondary wrote: "5xx are gone, but checkout's pool is climbing again. Is the cause actually fixed, or did something just reset it?" The postmortem has a "Symptom or cause" section naming the failover.
- **The training coach** moved with the player's actions, not with a Next button. Show me outlined the service to pick. The report said "Training complete" and led to a real shift.
- **Help:** it opened on the Checklist during the shift, with Acknowledge ticked.
- **New shift** from the report landed on the desktop with no windows, and the café was still mounted.

## Notes

- **Playwright's clock holds CSS and WAAPI animations mid-way**, so screenshots of a zoom in progress show a half-moved camera. This is a test artefact; the real-time e2e (`flow.spec.ts`, the report-fits and frame-time checks) covers the motion.
